# 청취 기록 정제 근거와 훈련·검증·테스트 시간 분할 검증

2026-11-10 · ListenBrainz 8주 전달본 · 기준 코드 `61a78e398bdafccd3ab41fc3ed9b21c4aaea7f9e`

과거 청취 기록만 확보한 시점에 기존 사용자에게 훈련 중 듣지 않은 곡을 추천하는 설정이다. 원본 9,350,628행을 기존 CLI로 처리했고, 독립 쿼리로 만든 기간별 사건 키 집합과 양방향으로 일치했다. 이 문서는 [공통 전처리 기준](../docs/preprocessing-plan.md), [데이터 계약](../docs/data-contract.md), [기존 정제·분할 실행 기록](cleaning-split-validation.md)을 근거로 삼는다.

## 입력 식별과 5,000명 표본

MetaBrainz Foundation / ListenBrainz 전체 덤프 2723의 전달본이다. 동봉 `source_manifest.json`의 스냅샷은 `2026-10-15 00:00:02.588811 UTC`이고 `COPYING`은 CC0 1.0 Universal이다. Parquet에는 `user_id BIGINT`, `listened_at TIMESTAMP`, `artist_name VARCHAR`, `recording_name VARCHAR`가 순서대로 있다. Parquet 메타데이터의 시각 정밀도는 마이크로초이며 시간대 표시는 없다. 부속 README의 명세대로 UTC로 해석하고 사건 키의 시각을 반올림하거나 초 단위로 절삭하지 않았다.

아래 바이트 수와 SHA256은 [고정 입력 기준](../config/raw-input-reference.toml) 및 [기존 기록](cleaning-split-validation.md)과 모두 일치했다. CLI와 독립 대조 모두 여섯 파일을 읽기 전용으로 열고 각각 실행 전후 지문이 같음을 확인했다.

- **기존 선정 기록.** `md5(str(user_id) + ":42") < "8"`로 해시 하위 절반의 후보를 읽었다. 2026-08-17~09-27 UTC의 과거 규칙으로 정규화한 고유 곡을 10개 이상 들은 20,284명 중 같은 해시의 오름차순 처음 5,000명을 선택했다고 기록되어 있다. 선정에 쓰인 정보는 사용자 ID의 고정 해시와 train 42일 동안의 이름 쌍이다. 이후 14일의 청취는 선정 뒤 해당 사용자에 대한 로그를 담는 데 사용되었다.
- **직접 확인.** CSV의 5,000행은 사용자 및 표시 ID가 각각 고유하고, Parquet 사용자 집합과 양방향 차이가 0명이다. 전달된 표본 안에서 해시 조건 위반과 `user_index` 순위 불일치는 각각 0명이다. 기존 공백 규칙을 train에 적용한 고유 곡 수는 CSV와 5,000명 모두 일치한다. 현재 공백 규칙에서는 8명의 수가 달라지지만 최소 고유 곡 수는 10이고 5,000명 모두 train 이력이 남는다. 기존 5,000명 전원을 유지했다.
- 추출 절차와 후보군 규모는 동봉 자료를 근거로 기록했다. 위 직접 대조는 전달된 표본의 순위와 train 이력에 적용했다. [원본 선정 기록](../docs/source-review.md)

## UTC 분할과 독립 대조

모든 사용자에게 같은 UTC 경계를 적용했다. 56일 중 연속된 42일을 두 모델의 과거 청취 이력으로 확보하고, 바로 이어지는 7일 구간 두 개에 각각 월요일부터 일요일까지 한 번씩 들어가게 했다. 달력 기간의 비중은 75%·12.5%·12.5%이며 사건 수는 실제 활동에 따라 달라진다. 이 시간 순서로 나중 청취가 과거 취향 추정에 섞이는 것을 막는다.

표의 날짜는 2026년 UTC다. 중복 초과 행은 train 394,735행, validation 73,938행, test 68,902행이다. 원본 행 수와 보존 수를 아래와 같이 대조했다.

```text
9,350,628 = (0 + 0 + 0 + 537,575) + (6,623,584 + 1,104,514 + 1,084,955)
```

[독립 대조 코드](../scripts/review_temporal_split.py)는 원본 Parquet에서 직접 고정 정규화와 유효성 조건을 적용해 사건 키를 그룹화한다. 계약에 명시된 UTC 경계로 기대 집합을 구성한 후, 같은 작업 DB에서 CLI가 호출하는 `build_clean_events`의 실제 출력과 각 구간을 두 방향으로 `ANTI JOIN`한다. 생산 `split` 열은 실제 집합을 나누는 데만 사용했다. 기존 보고서의 수치는 대조 후 참고값과 일치하는지 확인하는 데 사용했다. 동봉 README의 train 6,623,588건은 과거 공백 규칙의 집계다. 같은 원본에서 그 수치를 재현한 기록이 있으며, 현재 고정 규칙을 적용한 train은 4건 적다. [과거 규칙 재현](raw-data-audit.md)

- 기대 사건 중 소속이 0개 또는 2개 이상인 키 **0개**. 생산 사건에서 동일 키 중복 및 서로 다른 기간에 중복된 키 각각 **0개**. 계약에 없는 생산 split 또는 NULL **0행**.
- 건수를 유지한 채 validation과 test의 라벨을 서로 바꾼 합성 검사에서는 두 구간 각각 누락 1건과 초과 1건을 탐지했다.
- 같은 사용자의 활동이나 같은 곡의 청취가 여러 기간에 나타날 수 있다. 소속의 유일성은 전체 사건 키에 적용한다.

## 누수 검사와 기간별 역할

| 기간 | 용도 |
| --- | --- |
| train | 두 모델 학습과 사용자·곡 ID, 카탈로그, 표시명, 인기도, 청취 횟수 및 사용자별 기청취 이력을 결정한다. |
| validation | 모델 담당자가 알고리즘 설정과 인기 보정 강도를 선택한다. |
| test | 선택을 고정한 모델로 최종 평가한다. 카탈로그·이력은 최초 train을 그대로 사용한다. |

NFC, 공백, 필수값 및 중복 판정은 기간과 무관하게 미리 고정한 규칙이다. 원문 표시명과 곡별 청취자 수처럼 관측 빈도에서 산출하는 값은 train에서만 계산한다. 모델 담당자는 validation을 train에 합쳐 재학습하지 않는다. 후보는 train 카탈로그에서 해당 사용자의 train 기청취곡을 뺀 집합이다. validation에서 처음 들은 곡도 test에서 다시 들었고 train 카탈로그 및 사용자·후보 조건을 충족하면 test 정답이 된다.

- **시각 경계.** 2026년 네 경계의 1μs 직전과 정각에 정상 필드의 합성 사건을 넣었다. 08-17은 제외→train, 09-28은 train→validation, 10-05는 validation→test, 10-12는 test→제외였다. DuckDB 세션 시간대를 UTC·Asia/Seoul·America/Los_Angeles로 바꿔도 동일했다. NULL과 기간 밖 및 빈 이름이 겹치는 입력에서 우선순위를 확인했다.
- **훈련 사건과 빈도.** 동일 train을 두고 validation에만 20건 추가, test에만 20건 추가, 두 기간 모두 추가한 합성 예제에서 train 사건 전체, 사용자·곡별 횟수, 대표 이름과 그 빈도가 같았다. 같은 시각의 다른 곡과 다른 시각의 동일 곡을 보존하는 기존 사례도 통과했다.
- **훈련 ID·인기도·학습 데이터.** 기존 패키지 합성 테스트에서 미래 청취를 교체한 입력과 기준 입력의 `users`, `items`, `train_interactions` 전체 행이 일치했다. CSR의 shape, `indptr`, `indices`, `data`도 각각 같았다. 행 순서만 섞은 입력도 동일했다.
- **평가 구조.** 기존 합성 예제는 같은 미청취 곡 쌍이 validation과 test의 정답에 모두 남는 것을 확인했다. 후보가 9개인 사용자의 제외와 train 기청취곡·신규 곡의 제외도 검사했다. 정답 구조는 후보와 기간 규칙으로 검증했다.
