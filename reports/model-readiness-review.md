# 전처리 타당성과 모델 적합성 검토

고정 전처리 규칙을 적용한 학습 데이터의 진단 집계로 두 모델에 제공되는 신호와 한계를 설명한다. 배포 CSV의 검증 결과는 [CSV 검증 보고서](csv-dataset-validation.md)에 있다.

## 판정과 근거의 수준

**기본 전처리 규칙은 타당하며 두 추천 모델을 비교할 수 있는 학습 신호가 있다. 높은 추천 정확도와 인기 편향 개선은 아직 입증되지 않았다.** 전체 사용자 대비 항목 수, 동일 학습 패턴 곡, Item-based 동률, 시간 이상 신호, 메모리 사용 방식이 주요 위험이다. 데이터를 더 많이 정제하면 자동으로 성능이 좋아진다는 근거는 없다.

직접 관측한 주요 통계와 해석은 이 Markdown 보고서, 기본 검사값은 [원본 보고서](raw-data-audit.md)에서 Git으로 읽을 수 있다. 상세 기계 판독 통계인 `reports/model-readiness-diagnostics.json`은 로컬 생성물로 Git에서 제외되며 새 clone에는 없다. 재생성 명령은 아래 재현 명령에 있다. JSON 없이도 두 Markdown 보고서와 [전처리 계획](../docs/preprocessing-rules.md)·[데이터 계약](../docs/data-contract.md)을 읽고 공통 전처리 준비를 시작할 수 있다. 아래에서 통계·수학적 추론·미검증 항목을 구분한다. 모델을 학습하거나 실제 추천 목록·Recall·ARP를 계산하지 않았다. 수학적 Recall 상한과 양의 유사도 경로 비율은 모델 성능 측정값이 아니다.

| --- | --- | --- |
| 기본 정규화·중복·분할 | 타당한 보수적 기본값 | 유지, 최종 생성 코드의 불변식 검사 |

| Implicit MF | 희소 입력으로 계산 가능성이 있음 | confidence·손실식 확인과 전체 카탈로그 실행 점검 |
| 로그 의미 품질 | 시간 묶음·유사 계정 사례 관측 | 학습 기준 진단 플래그, 원본 보존, 자동 삭제 보류 |
| 평가 설계 | 현재 목적에 맞는 고정 시간 분할 | 전체 후보·기간별 동일 사용자 유지, 지표 해석 보완 |
| 높은 정확도·보정 효과 | 아직 미검증 | 모델 담당자의 검증 실험으로 확인 |

## 전처리 규칙의 타당성

NFC와 공백 정리로 원본 9,350,628행 중 12,438행의 이름이 달라졌으며, 원문 이름 튜플의 감소는 268개다. 합쳐진 정규화 키는 267개이고 한 키의 원문 변형은 최대 3개다. 대규모 의미 병합을 수행한 결과가 아니다. 대소문자·구두점·버전 표기를 유지하고 두 필드 튜플로 식별하는 기본값은 서로 다른 음원 오병합을 줄이는 방향이다.

동일 사용자·시각·정규화 곡의 초과 행만 제거하고 다른 시각 반복을 보존하는 규칙은 횟수 부풀림과 실제 반복 신호 사이를 구분한다. 단, 같은 초에 같은 곡을 실제로 중복 재생한 사건인지와 중복 제출인지는 네 필드만으로 확정할 수 없다. 초과 행을 중복 후보로 처리한다는 운영적 가정을 명시해야 한다.

시간 분할은 전역 UTC 반개구간이며 ID·카탈로그·대표 이름·횟수·인기도를 train에서만 만드는 규칙은 정보 누출을 방지한다. 고정 NFC/공백 함수 자체는 미래 정보로 학습되지 않는다. 실제 CSV의 ID·표시명·횟수·인기도·평가 정답은 원본 기반 독립 검사로 대조한다.

전체 기간에서 소문자화하면 추가로 합쳐질 수 있는 이름 쌍은 20,243개다. 이것이 전부 같은 음원이라는 근거는 없다. 단순 소문자화만으로 현재의 학습 sparsity를 해결한다고 기대하기도 어렵다. 동명 음원·리마스터 차이·원문 매핑 차이는 MBID가 없는 데이터의 잔여 한계다.

이름에 U+FFFD 대체문자 24행, U+200B/BOM 293행, 공백 외 제어문자 246행을 관측했다. 세 범주는 중복될 수 있다. 원본 문자 복원이 불가능한 사례도 있으므로 일괄 삭제·추측 교정하지 않는다. 출력 시 개행·마크업·제어문자를 형식에 맞게 처리하되 ID 키를 임의로 바꾸지 않는다.

### Item-based의 구체적인 동률 문제

한 사용자 v만 들은 곡 i의 양수 청취 벡터는 `a·e_v`이고 같은 v만 들은 다른 곡 j는 `b·e_v`다. 따라서 일반 cosine similarity는 `a·b/(a·b)=1`이다. 로그 횟수로 바꿔도 a,b가 양수이면 같다. 이는 [Item-based 원문의 cosine similarity 정의](https://archives.iw3c2.org/www10/cdrom/papers/519/node12.html)를 현재 데이터 구조에 적용한 수학적 추론이다.

이런 곡을 가진 사용자 4,944명의 단독 항목 수 중앙값은 105.0개, 최대는 10,510개다. 2,524명은 100개를 넘는다. K=10이나 100으로 이웃을 남기면 동일 유사도 곡 중 어느 것을 택하는지가 크게 작용할 수 있다. 일부 구현에서 자기 자신·이미 들은 곡들이 이웃 공간을 차지하면 실제 새 곡 점수가 부족해질 수 있다.

필요한 대응은 결정적 동률·자기 자신 제외·이웃 방향·0점 및 10개 미달 처리의 명시, 전체 후보 유지, 결과의 동률 비율 보고다. 지지도 기반 유사도 보정은 별도 모델 설정으로 검토할 수 있으나 공통 데이터에 적용하지 않는다. 저인기 곡을 삭제하는 해결책은 기본안에 넣지 않았다.

### MF도 항목을 구분할 근거가 부족한 경우

1인 청취 항목 중 소유 사용자와 listen_count까지 같은 열 패턴은 30,911종이다. 같은 패턴이 반복되는 묶음에 속한 항목은 1,194,725개이고, 가장 큰 묶음은 9,051개다. 동일한 상호작용 열과 동일한 인기도만 가진 곡은 MF에 제공되는 관측 근거도 같다. 무작위 초기값이나 ID 순서가 차이를 만들 수 있어도 곡별 적합도를 구별하는 증거가 새로 생기는 것은 아니다.

따라서 MF가 sparsity를 자동으로 해결한다고 가정하지 않는다. 현재 데이터는 비교 실험에 사용할 수 있지만, 모든 저인기 곡을 세밀하게 구별하는 서비스 수준 추천을 보장하지 않는다. 장르·음향 특성·음원 식별자 등 추가 정보 결합은 필요성과 비용을 별도로 판단할 확장 범위다.

## 정답 곡과 연결되는 학습 신호

대상 사용자 u가 학습에서 들은 곡 j와 정답 i를 함께 들은 학습 사용자가 있으면, 양수 log-count 또는 binary 벡터에서 j–i의 cosine similarity가 양수일 수 있다. 모든 학습 이력 곡에 대해 이 경로가 있는지 검사했다. Top-K 절삭은 적용하지 않았다.

| 항목 | validation | test |
| --- | --- | --- |
| 평가 사용자 | 3,922 | 3,852 |
| 정답 쌍 | 193,323 | 201,203 |
| 양의 유사도 경로가 있는 정답 쌍 | 182,777 | 189,146 |
| 전체 정답 쌍 기준 비율 | 94.54% | 94.01% |
| 사용자별 경로 비율의 평균 | 89.66% | 89.23% |
| 정답에 이러한 경로가 전혀 없는 사용자 | 78 | 89 |

이는 유용한 신호가 존재한다는 근거다. 점수 크기·상위 10개 진입·Top-K 이웃 유지·학습 후 MF 성능을 보장하지 않는다. 경로가 없는 곡도 0점 동률이나 별도 모델 점수로 추천될 수 있으므로 이 비율을 모델 Recall의 엄밀한 상한으로 쓰지 않는다. 같은 connected component라는 사실만으로 직접 cosine similarity 경로를 인정하지 않도록 작은 반례 테스트를 추가했다.

학습 항목 50개 미만인 테스트 사용자 222명의 사용자별 경로 비율 평균은 64.88%다. 전체 평균보다 낮으므로 짧은 이력 사용자에 대한 결과를 별도로 해석해야 한다. 이 이유로 해당 사용자를 제거하지 않는다.

## 로그 품질 신호와 영향

### 동일 시각에 서로 다른 곡 다수 기록

학습에서 같은 사용자·같은 시각에 여러 곡이 있는 시각은 256,142개이며 해당 사건은 523,096건이다. 최대는 572곡·402아티스트가 한 시각에 기록된 사례다. 다른 곡이므로 현재 중복 키로는 제거되지 않는다. 다중 기기·타임스탬프 반올림·기록 이관/동기화·비정상 제출 등 가능한 원인은 많고 네 컬럼만으로 원인을 확정할 수 없다.

| 구간 | 동시각 10곡 이상 시각 수 | 영향 사용자 | 해당 사건 | 동시각 최대 곡 수 |
| --- | --- | --- | --- | --- |
| test | 12 | 7 | 230 | 43 |
| train | 94 | 42 | 2,146 | 572 |
| validation | 40 | 13 | 781 | 60 |

학습의 동시각 10곡 이상 사건 2,146건은 학습 사건의 0.03%다. 검증 정답 126쌍, 테스트 정답 106쌍은 해당 평가 기간의 이러한 묶음에 한 번 이상 등장했다. 정답 쌍이 다른 정상 시각에도 등장할 수 있어 이 수치를 곧바로 삭제 영향으로 해석하지 않는다. 10/100은 기술통계 구간이며 새 필터 임계값이 아니다. 큰 극단 사례의 전체 비중은 작지만, 2곡 동시 기록까지 모두 정상 또는 모두 오류라고 판정할 근거도 없다.

전처리 시 플래그와 집계를 남기고 기본 데이터는 보존한다. 강한 정제를 검토할 때는 학습 정보에서 근거·제외 영향·민감도 설계를 먼저 고정하고 중요한 변경을 확인한다. 평가 성능이 좋아지는 방향으로 삭제 규칙을 고르지 않는다.

### 거의 동일한 두 사용자 청취 이력

학습 고유곡 집합이 정확히 같은 서로 다른 사용자쌍은 1쌍이다. 표시 ID U0240/U1761은 각각 403곡을 가지며 학습 사건 1,271건/1,270건 중 1,270건의 곡과 시각이 일치했다. 동기화·중복 계정 등의 가능성을 강하게 시사하지만 동일 인물이라고 확정할 정보는 없다. 원본 ID나 이름을 공개하지 않았다.

이 사용자들을 완전히 독립적인 취향 근거로 해석하면 일부 곡의 고유 청취자 수가 부풀려질 수 있다. 자동 병합/삭제·재표본 추출은 하지 않았다. 정제 담당자가 확인할 사례로 남기며, 가까운 프로필 표본의 전체 목록과 시각 대조 결과는 로컬 진단 JSON에 있다. 필요하면 아래 명령으로 재생성한다. 이 신호만으로 동일인 여부를 판정할 수 없다.

### 반복 청취·사용자 집중

학습 청취 상위 1명은 전체 사건의 0.94%, 상위 1%인 50명은 19.81%, 상위 10%는 54.45%를 차지한다. 반면 고유 상호작용의 상위 1% 비중은 9.21%다. 반복 강도가 큰 사용자가 횟수 기반 학습을 지배할 위험이 있다. 학습 user-item 횟수 중앙값은 1, 99분위수는 16, 최대는 14,113이다.

고유 사용자 수 인기도는 동일 사용자의 반복으로 직접 증가하지 않는다. Item-based의 로그 변환·MF의 confidence 강도와 정규화는 모델 담당자가 검증할 항목이다. 원시 횟수 전달을 유지해 변환 선택을 재현 가능하게 한다. 학습에서 하루 1,440건 초과는 6명·39활동일이었지만 이 숫자로 자동 삭제하지 않았다.

## 평가 결과를 오해할 수 있는 지점

### Recall@10은 이 데이터에서 1까지 올라갈 수 없다

사용자 정답이 T개면 추천 10곡으로 얻을 수 있는 Recall의 최대는 `min(10,T)/T`다. 이를 현재 평가 사용자에 대해 평균했다.

| 항목 | validation | test |
| --- | --- | --- |
| 정답 수 중앙값 | 29.0 | 31.0 |
| 정답 수 최대 | 856 | 1260 |
| 정답이 10개를 넘는 사용자 | 2944 | 2940 |
| 완벽한 정답 순위를 가정한 Recall@10 상한 | 0.478478 | 0.464331 |

이 값은 추천 실험 결과가 아니라 지표 정의로 계산한 상한이다. 다른 데이터셋의 Recall 수치와 직접 비교해 품질을 단정하지 않는다. 균등 무작위 10곡 추천의 기대 Recall은 약 0.00000656이다. 무작위 기대값 초과만으로 좋은 개인화라고 결론 내리지 말고 모델 담당자가 인기순 기초 방식 등 의미 있는 기준과 비교해야 한다.

### 신규 곡 제외와 평가 사용자 선택

학습 밖 곡의 사건 비율은 검증 20.70%, 테스트 23.55%다. 고유 user-item 쌍 기준 제외 비율은 각각 29.22%, 31.57%다. 사건 비율과 고유쌍 비율을 구분해야 한다.

평가 사용자 비율은 원래 5,000명 대비 검증 78.44%, 테스트 77.04%다. 활동이 없거나 후보에 속한 정답이 없는 사용자는 평가되지 않는다. 결과는 기존 사용자·학습 카탈로그·미청취곡이라는 조건의 오프라인 성능이며 신규 곡·신규 사용자·실제 만족도를 포함한 서비스 전체 성능으로 일반화하지 않는다.

테스트 정답 중 56.86%는 사용자 자신의 학습 이력에 없는 아티스트다. 단순히 같은 아티스트만 추천하는 후보 제한을 적용하면 다수 정답을 놓칠 수 있다. 이는 그 아티스트가 전체 학습에 없다는 뜻은 아니다.

주별 정제 사건 수는 약 106.8만~112.5만 건으로 큰 누락이나 사건 수 급변은 관측하지 않았다. 이것만으로 취향·항목 인기도 분포가 안정적이라고 판정할 수는 없다. 전체 주별 통계는 로컬 진단 JSON에 있으며 필요하면 아래 명령으로 재생성한다.

검증·테스트의 공통 평가 사용자는 3,560명, 공통 정답 쌍은 18,279개다. train을 고정하면 두 기간에 같은 정답이 다시 나타날 수 있으며 현재 규격에 부합한다. 검증을 학습에 합치거나 검증 청취곡을 테스트 후보에서 추가로 빼면 실험 조건이 달라진다.

전체 후보 평가 유지가 타당하다. 후보를 임의 표본으로 줄이면 모델 간 비교 순위까지 달라질 수 있음이 [Krichene·Rendle의 연구](https://ijcai.org/proceedings/2021/651)에 제시되어 있다. 계산 문제는 후보 정의 변경보다 사용자/블록 단위 점수 계산으로 대응한다.

### 인기 편향 개선의 해석

ARP 감소만으로 추천 품질 개선을 주장하지 않는다. 낮은 지지도 곡의 임의 동률 선택도 ARP를 낮출 수 있다. 같은 사용자·후보·정답으로 Recall과 ARP를 함께 비교하고 추천 10개가 모두 유효한지 검사한다. 보정을 끈 기준 모델과 비교하고, 난수 시드를 바꿔도 검증 결과가 일관적인지 확인한다. 가능하면 사용자별 차이와 불확실성도 보고하고 테스트로 설정을 고르지 않는다.

## sparse matrix와 모델 구현의 계산 범위

아래는 현재 크기에서 배열 원소 수로 계산한 바이트다. GB는 10억 바이트이고 실제 프로세스는 추가 작업공간·인덱스·복사본을 사용한다.

| 대상 | 배열 크기 추정 |
| --- | --- |
| 원시 int64 횟수 CSR (int32 구조 가정) | 32.89 MB |
| 사용자×곡 float32 dense | 30.50 GB |
| 곡×곡 float32 dense | 9.30 TB |
| MF 64차원 사용자·곡 float32 요인 | 391.68 MB |
| 한 번에 32명 전체 곡 점수 float32 | 195.20 MB |
| 항목당 최대 이웃 100개 float32값+int32구조 | 1.23 GB |

희소 입력과 작은 잠재 차원은 메모리 관점에서 가능성이 있다. 전체 점수나 전체 유사도에 필요한 dense matrix 크기는 아래 규모 비교를 따른다. 입력이 희소해도 `X.T @ X` 전체를 만든 뒤 Top-K를 자르면 중간 결과가 커질 수 있다. 사용자별 항목 조합 발생 수 `Σ degree(u)(degree(u)-1)`은 4,269,980,456이다. 이는 중복을 포함한 계산량 지표이며 고유 유사도 행렬의 nnz 측정값은 아니다.

Item-based는 블록 또는 계산 도중 상위 이웃을 유지하는 구현을 점검해야 한다. MF는 사용자 수보다 항목 수가 훨씬 많아 모든 항목 요인을 갱신하는 시간과 보정 손실 최적화 비용이 남는다. Colab을 써도 dense 전개나 전체 조합 SGD는 해결되지 않는다. 실제 모델 학습 시간·GPU 호환성·메모리 최고치는 실행하지 않아 아직 미검증이다.

### 모델 API와 수식 대응

[Hu·Koren·Volinsky 원문](https://yifanhu.net/PUB/cf.pdf)은 선호 p와 신뢰도 c를 구분한다. [implicit CPU ALS 공식 코드](https://github.com/benfred/implicit/blob/main/implicit/cpu/als.py)를 확인하면 입력은 사용자×항목 CSR이며 값은 confidence이고 alpha가 이를 추가 배율 조정한다. 원시 청취 횟수 `n`을 목표 confidence `c = 1 + αn`으로 변환하는 과정과 alpha 적용 방식을 작은 예제로 검증한다. alpha가 중복 적용되지 않는지, 행렬의 사용자 축과 항목 축이 올바른지도 확인한다.

관측 손실에 양수 가중치 w를 곱하는 일부 설계는 관측 confidence를 w·c로 표현할 수 있다. 따라서 해당 라이브러리에서 보정이 무조건 불가능하다고 단정하지 않는다. 미관측 항목의 confidence, 정규화, 손실 스케일이 구현하려는 목적 함수와 일치하는지 확인한다. 실제 채택 라이브러리의 버전을 고정한 뒤 같은 확인을 반복해야 한다. 이 확인과 가중치 계산은 모델 담당자가 수행한다.

## 공통 데이터와 모델 검증

공통 패키지의 ID·원시 횟수·정답·제외 집계는 [CSV 검증](csv-dataset-validation.md)에 있다. 모델 담당자는 전체 카탈로그를 기준으로 동률·0점·10곡 미달 처리, confidence와 손실식의 대응, 인기 보정 강도 0의 기준 모델 복원을 확인한다. 설정은 validation에서 선택해 고정하고 test에서 오프라인 성능과 인기도를 비교한다.
