- UTC 2026-08-17 00:00:00 이상, 2026-10-12 00:00:00 미만의 56일.
- user_id, listened_at, artist_name, recording_name 네 컬럼.
- 날짜/사용자/컬럼을 선택한 추출본이며 이름 정규화나 중복 제거는 적용하지 않았습니다.
- selected_users.csv: 원본 사용자 ID, 학습 구간 이름 조합 수, 내부 user_index.
- 사용자 이름은 포함하지 않습니다. 보고서와 화면에는 user_index를 사용하세요.

이용 조건과 출처
- 원본: ListenBrainz 전체 덤프 2723, 2026-10-15 00:00:02.588811 UTC 기준.
- source_manifest.json에 정확한 공식 URL과 34개 Parquet의 원본 위치가 있습니다.
- 원본 TAR의 COPYING에서 CC0 1.0을 확인했으며 파일을 동봉했습니다.
- 음원 파일은 포함하지 않으며 청취 기록의 이용 조건이 음원 권한을 의미하지는 않습니다.
- 제공 기관 MetaBrainz Foundation과 ListenBrainz를 출처로 표기하세요.
- 공식 Spark용 내보내기는 매핑된 곡에 보정된 이름을 사용하고, 미매핑 곡은 원래 제출 이름을 유지합니다.
  참고: https://github.com/metabrainz/listenbrainz-server/blob/master/listenbrainz/listenstore/dump_listenstore.py
- 별도 MusicBrainz API나 외부 데이터 수집·결합을 수행하지 않았습니다.

추출과 검증
- 전체 TAR 248,635,791,360바이트를 통째로 내려받지 않고 HTTP Range로 헤더/푸터/필요 컬럼을 읽었습니다.
- 번호 1476~1509의 연속 파일과 시간 경계를 확인했습니다. 원본의 대상 기간은 74,043,337행입니다.
- md5(str(user_id)+":42") < "8"인 해시 하위 절반을 후보군으로 읽었습니다.
- 후보군에서 학습 구간(8/17~9/27)에 NFC·연속 공백 정리 후 서로 다른 (아티스트, 곡명)을 10개 이상 들은 사용자는 20,284명입니다.
- 이들을 같은 해시의 오름차순으로 정렬해 앞 5,000명을 선택했습니다. 후보군 밖은 해시가 더 크므로 이 선택 순위에 영향을 주지 않습니다.
- 미래 청취 여부로 선정하지 않았고 사용자별 상위곡·좋아요곡 제한이나 저인기 곡 제거를 하지 않았습니다.
- 전체 TAR의 공식 SHA256 검증을 한 것은 아닙니다. 필요한 Parquet 컬럼을 실제 디코딩해 추출했고, 전달 파일의 SHA256을 별도로 저장했습니다.
- 전달 파일 SHA256: 4beecfca926a472081b70bcc50c2a20193756a90f9e8dc84336076e86b72e3c3

검증용 집계와 팀 전처리의 구분
- 원문 이름 조합 수: 1,856,579개.
- 동일 user_id/listened_at/artist_name/recording_name 키의 중복 후보: 537,555행.
- 이름 NFC·공백 정리와 해당 키 중복 제거를 적용한 검증용 사건: 8,813,057행.
- 검증용 정규화 이름 조합: 1,856,351개. 정확한 고유 음원 수와 다를 수 있습니다.
- 원본 추출본의 행은 삭제하지 않았습니다. 중복/이름/비음악 콘텐츠/과도한 청취량 등 최종 전처리 규칙은 팀에서 정하세요.
- 사용자 1인 1일 최대 관측 사건은 2,406건이므로 이상치 여부를 점검하세요. 수량만으로 자동 삭제하지는 않았습니다.

읽기와 검증
검증 실행 환경: Python 3.12, DuckDB 2.0.0.
python -m pip install -r requirements.txt
python verify_dataset.py

DuckDB 예시
import duckdb
con = duckdb.connect()
con.sql("SELECT * FROM 'listens_8weeks_5000users.parquet' LIMIT 5").show()

Pandas로 읽으려면 pandas와 pyarrow를 설치한 뒤 pd.read_parquet(...)를 사용할 수 있습니다.
145 MB는 압축 파일 크기이며 메모리 사용량과 같지 않습니다. 필요한 컬럼만 읽고 희소행렬을 사용하세요.

재추출
python reextract_dataset.py
이 작업은 공식 서버에서 약 1.4 GB의 컬럼 데이터를 다시 읽습니다. 이미 제공된 데이터 파일을 쓰면 재실행할 필요가 없습니다.
재추출 파일은 기록과 범위 재현을 위한 것이며 쓰기 순서 등에 따라 파일 바이트/해시는 달라질 수 있습니다.
공식 서버가 과거 덤프를 삭제할 수 있으므로 전달 파일과 출처 정보를 함께 보관하세요.
